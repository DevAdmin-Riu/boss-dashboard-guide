=== 목표 ===
routes.json의 각 path마다 해당 페이지 “전용” 이용 가이드(특별 기능/유의사항 중심)를 Docusaurus 문서로 생성한다.

=== 입력(저장소 루트 기준) ===
- ./generated/routes.json
- ./generated/repomix-outputs/fe-dashboard.xml (프론트 repomix 압축/파일)
- ./generated/repomix-outputs/be.xml (백엔드 repomix 압축/파일)

=== 출력 규칙 ===
- DOC_ROOT: 저장소 루트 기준 ./docs
- DOC_ROOT 하위에 파일 생성/수정
- 각 path는 {DOC_ROOT}{path}/index.md 로 생성 (예: /a/b -> docs/a/b/index.md)
- 각 index.md는 front matter 포함:
  - title: routes.json의 menuLabel 요소들을 " > "을 사이에 두며 이어 붙인 문자열 (예: menuLabel = ["재고 발주 관리", "재고 발주"]이면 "재고 발주 관리 > 재고 발주")
  - slug: routes.json의 path
  - sidebar_position: routes.json의 sidebarOrder

=== 작성 규칙(중요) ===
1) 코드 네이밍은 “근거 찾기”에만 쓰고, 본문에는 절대 노출하지 말 것.
2) 기능 설명은 “유저 행동 흐름”으로만 작성:
   - 어디를 클릭/입력/선택 → 다음 화면/모달에서 무엇을 함 → 저장/확정 → 성공 여부를 무엇으로 확인
3) “공통 기능(필터 검색/페이징/정렬/조회결과 다운로드 등)”은 작성하지 말 것.
4) 완료 확인(성공 기준)을 반드시 포함:
   - 목록에 새 항목이 보인다 / 상태 뱃지가 바뀐다 / 완료 토스트가 뜬다 / 다운로드 파일이 생긴다 등
5) 무조건 해당 페이지에서 관리자 유저(isStaff=true)에게 노출되는 UI 텍스트를 기준으로 작성할 것.
   - 예: "포장보스 제품정보 일괄 등록/수정" 버튼, "신규 제품 생성" 버튼 등
   (임의로 구체 문구를 만들어내지 말 것)
6) [이 페이지에서 하는 일]은 1~2 문장으로 간략하게 작성, [실패/제한/주의], [상태/조건에 따른 표시/가능 작업 차이]는 있을 때만 작성할 것.
