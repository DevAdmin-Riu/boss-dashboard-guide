=== 목표 ===
- 저장소 루트 기준 `./generated/repomix-outputs/fe-dashboard-urls.xml`의 코드 패킹 결과를 분석해서,
- 관리자 기준(isStaff=true) 서비스의 메뉴/페이지 경로(pathname) 목록을 정리한 `routes.json` 파일을 생성해줘.

=== 중요 원칙(추측 금지) ===
- menuStructureStaff.ts 파일 내에 명시된 url에 대해서 빠짐 없이 파악할 것.
- 실제 코드에 근거하지 않는 경로(path)를 만들어내지 말 것.
- 확실치 않으면 결과에 포함하지 말 것.

=== 출력 파일 생성 ===
- 저장소 루트 기준 `./generated/routes.json` 파일을 생성(또는 덮어쓰기)하라.

=== routes.json 스키마(반드시 이 형식) ===
- JSON 배열만 포함해야 한다. (설명/주석/코드블록 금지)
- 각 원소는 아래 필드를 가진다.
- 각 원소 순서는 createStaffMenuStructure에 위에서부터 선언된 순서를 기준으로 하되, navUrlList가 있는 요소의 path는 관련 urls.ts 파일 내에서 "~UrlList" 변수에 선언된 순서로 작성

=== 필드 규칙 ===
- path:
  - 반드시 "/"로 시작
  - 쿼리스트링/해시(#) 포함 금지
  - trailing slash는 제거(루트 "/"는 제외)
  - "/"(메인) 페이지는 제외 (이번 사이트는 메인 페이지 없이 운영한다)
  - routeParams 구조를 파악 후, 실제로 리턴되는 결과 url을 작성할 것.
- menuLabel:
  - 해당 페이지 진입 시 활성화되는 좌측 메뉴의 구조
  - createStaffMenuStructure의 label을 뎁스 순서대로 정리한 문자열 배열
  - createStaffMenuStructure의 navUrlList가 있는 메뉴의 경우, 관련 urls.ts 파일 내에 선언된 변수(각각 "NavButtonName", "UrlList"로 끝나는 네이밍으로 선언됨) 참고하여 해당 url이 연결된 버튼 텍스트까지 요소로 추가
    예) path가 "/b2b/order/accept" 인 경우, menuLabel = ["B2B", "주문", "주문 접수"]
- sidebarOrder:
  - createStaffMenuStructure 기준으로 렌더링될 때, 최상단으로부터 렌더링 되는 순서

=== 작업 절차(네가 수행) ===
1) ./generated/repomix-outputs/fe-dashboard-urls.xml 파일 확인
2) 위 규칙으로 routes 목록을 확정
3) 저장소 루트 기준 ./generated 경로에 routes.json 생성/저장

=== 마지막 출력 ===
- 파일 생성이 끝나면 콘솔에 한 줄만 출력:
  - "routes.json generated: N routes"
- (콘솔에 JSON 본문을 출력하지 말 것. 파일로만 저장)
